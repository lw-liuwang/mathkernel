# v0.3.0：可执行的变换链与证明复用

Agent 可以使用任务模型提供的已证明规则构造多步变换，同一组规则和基线证明可用于多个候选。工具执行变换、组合候选正确性证明，并在验收时重放完整推导。

## 新增接口

- Lean 模型增加可选 `transformations` 列表，默认 `[]`。每条 `Workflow.Transformation execute` 提供名称、参数说明、应用函数和成功应用时的等价性证明。
- `task rules DIRECTORY` 返回任务规则目录，可在确认前查看，不启动探索预算。
- 候选 JSON 可用非空 `derivation` 列表代替 `plan`，每步提供 `rule` 和 `arguments`。变换链的证明文件只需提供 `baselineCorrect`。
- `derivation.json` 和产出包的 `scheme.json` 保留规则、参数、逐步方案及公式；失败应用返回步骤编号、原因和此前成功步骤。

变换链作为一个候选计入预算。最终方案仍须通过资源约束和目标改进检查；中间步骤可以增加成本。规则和参数由 agent 选择，本版不增加自动搜索或具体数学规则库。

## 升级与验证范围

直接提交方案和完整证明的流程继续使用。任务协议版本仍为 1；公共 Lean 来源变化会使已有任务的确认和证据失效，升级后需重新确认、评价和验收。已有产出包继续使用生成它的 MathKernel 版本重新验收。

本版使用合成任务检查多步组合、规则及基线证明复用、失败诊断、公理检查、成本与容量限制，以及离开原任务目录后的独立验收。这些场景验证通用机制，不代表真实 kernel 的优化效果。数值语义和成本模型范围保持原有定义。
